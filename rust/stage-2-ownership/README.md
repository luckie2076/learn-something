# 阶段 2：所有权与借用（重点单元）

本阶段是 **Rust 最核心、也最能体现"Rust 与 C 的血缘关系"**的部分。你有 C 基础，这里的每个概念都能对应到 C 的某个内存操作——你会看到 Rust 把 C 程序员靠纪律维护的内存安全，变成了编译器的硬规则。值得放慢脚步，反复读两遍。

```bash
cd stage-2-ownership
cargo run
```

## 0. 先回答"为什么"：内存管理的三种方案

每个程序都要管理内存。历史上三种方案：

| 方案 | 代表语言 | 做法 | 代价 |
|------|---------|------|------|
| 垃圾回收（GC） | Python / JS / Java | 运行时自动回收没人用的内存 | 运行时开销 + 回收时机不确定 |
| 手动管理 | C / C++ | 程序员自己 `malloc` / `free` | 极易出错（内存泄漏、悬垂指针、double free） |
| **所有权** | **Rust** | **编译器在编译期**检查谁拥有内存，编译通过即内存安全 | 需要学习一套新规则（就是本阶段） |

**Rust 的选择**：没有 GC 的运行时开销，也不用手动管理——把"谁拥有这块内存、何时释放"这件事交给编译器在**编译时**算清楚。这就是 Rust 的"内存安全，无需 GC"。

对你来说，最好的理解路径是**从 C 出发**：你手写过的 `malloc`/`free`、踩过的悬垂指针和 double free，在 Rust 里全部被编译期规则消灭，但心智模型完全一致（堆、栈、指针、生命周期）。

## 1. 所有权三规则

1. **每个值都有一个所有者（owner）变量**。
2. **同一时刻只有一个所有者**。
3. **所有者离开作用域时，值被自动释放**（`drop`）。

```rust
{
    let s = String::from("hello"); // s 拥有这个 String
    // ... 使用 s ...
} // 作用域结束，s 被 drop，内存自动释放
```

> 对照 C：`String::from(...)` 相当于 `malloc` + 初始化，而"离开作用域自动 `drop`"相当于**编译器帮你调用 `free`**——绝无遗漏、绝不重复。

## 2. 移动（Move）：赋值不是拷贝

```rust
let s1 = String::from("hello");
let s2 = s1;          // s1 的所有权"移动"到 s2
// println!("{s1}");  // 编译错误！s1 已失效
println!("{s2}");     // OK
```

**为什么？** `String` 的数据在堆上，`s1` 只存"指针+长度+容量"（fat pointer）。如果 `let s2 = s1` 做浅拷贝，两个变量会指向同一块堆内存，作用域结束时会 **double free**（释放两次）。

你在 C 里一定写过这种 bug：

```c
char *s1 = malloc(6);
char *s2 = s1;      // 浅拷贝：两个指针指向同一块内存
free(s1);
free(s2);           // double free！未定义行为
```

Rust 的处理更干脆：**赋值即转移所有权，旧变量立刻失效**——编译器保证同一时刻只有一个所有者，所以绝不会 double free。`let s2 = s1` 等价于"C 的浅拷贝 + 立刻把 `s1` 置为失效"。

> 这也意味着 Rust 没有"隐性深拷贝"。`s1` 之后还能用的话，必须显式 `s1.clone()` 做深拷贝（对应 C 的 `strdup`），成本一目了然。

**标量类型（i32、bool、char…）则相反**：它们实现了 `Copy` trait，赋值是"拷贝"，旧变量仍可用：

```rust
let x = 5;
let y = x;        // x 仍然有效（栈上的值，拷贝无成本）
println!("{x} {y}");
```

> 对应 C 的直觉：`int x = 5; int y = x;` 是纯栈上拷贝，没有任何问题。Rust 用 `Copy` 标记"可以按值拷贝的类型"，与 `move` 的语义由类型自身决定。

## 3. 函数传参与返回值：所有权跟着走

```rust
fn take(s: String) {   // s 拿到所有权
    println!("{s}");
}                      // 函数结束，s 被 drop（自动 free）

let s = String::from("hi");
take(s);               // 所有权转移进函数
// println!("{s}");    // 编译错误
```

函数返回时所有权也会"还回来"（返回值的所有权交给调用者）。这是 Rust 无 GC 也能安全的关键：所有权总是清晰地从一处转到另一处。

> 对照 C：C 里函数接收 `char *s` 时，谁负责 `free` 全靠函数文档约定（有的函数拥有、有的只读）。Rust 把这个约定**写进了类型系统**：传 `String` 表示"给你，你负责释放"，传 `&String` 表示"我只借用"。

## 4. 借用（Borrowing）：`&` 只借不拿

如果每个参数传递都转移所有权，代码会变得很难用。于是有了**引用**：

```rust
fn borrow(s: &String) {  // & 表示"借用"，不拿走所有权
    println!("{s}");
}

let s = String::from("hi");
borrow(&s);              // 借出去，s 仍然是所有者
println!("{s}");         // OK！s 还能用
```

> 对照 C：`&s` 就是"取地址传指针"——`void borrow(const char *s)`。借用 = C 的传指针但不转移释放责任。

借用规则（编译器强制）：
1. **任意时刻，要么有一个可变引用（`&mut`），要么有多个不可变引用（`&`），二者不能共存**。
2. **引用必须始终有效**（不能产生悬垂引用——引用指向的内存已被释放）。

```rust
let mut s = String::from("hello");
change(&mut s);          // 可变引用：可以修改（对应 C 的非 const 指针传参）

let r1 = &s;             // 多个不可变引用 OK
let r2 = &s;             // 同一时刻允许"多个读者"
// let r3 = &mut s;      // 编译错误！不可变引用还在时不能可变借用
```

**为什么这么严格？** 数据竞争（data race）：两个线程同时读写同一内存会导致未定义行为。Rust 在编译期就禁止了"同时可变 + 不可变访问"，所以**数据竞争在 Rust 中编译不过**。

> 对照 C：C 里 `void f(const char *s, char *out)` 的"const 约束"全凭调用者自觉，多个线程共享可变指针时更是毫无保护。Rust 把 `const` 指针（`&`）与可变指针（`&mut`）的互斥关系变成了编译期硬约束——这正是 Rust 相对 C 的最大卖点之一。

## 5. 悬垂引用（Dangling Reference）：想都别想

```rust
// fn dangle() -> &String {
//     let s = String::from("hello");
//     &s           // 编译错误！s 在这里就被释放了，返回的是悬垂引用
// }
```

编译器直接禁止：**引用不能活得比它指向的值更久**。

> 对照 C：这就是你踩过的 **use-after-free**——函数返回了指向栈上局部变量的指针，或 `free` 之后继续用指针。C 里这是运行时的未定义行为（可能正常、可能崩溃、可能被利用），Rust 在编译期就拦下了。

## 6. 切片（Slice）：集合的"只读窗口"

切片是对集合一部分的**借用**，类型 `&str` / `&[i32]`：

```rust
let s = String::from("hello world");
let hello = &s[0..5];   // "hello"，&str 切片
let world = &s[6..11];  // "world"

let arr = [1, 2, 3, 4, 5];
let slice = &arr[1..3]; // [2, 3]，数组切片
```

> 对照 C：切片 = "指针 + 长度"。C 里把数组某一段传给函数时，要传两个参数（`char *ptr, int len`），Rust 把这两个打包成一个类型 `&[i32]`，并且边界由编译器/运行时保证——不会越界。
> 阶段 1 里说"字符串字面量类型是 `&str`"——现在能理解了：字面量就是"对整个二进制里那段只读字符串的切片借用"，对应 C 里指向只读字符串字面量的 `const char *`。

## 常见坑

- **`value borrowed here after move`**：用了已被移动的变量。要么不再用，要么 `clone()`（对应 `strdup`），要么改用 `&` 借用。
- **`cannot borrow as mutable because it is also borrowed as immutable`**：不可变借用与可变借用重叠了（相当于同时持有 `const char *` 和 `char *`），调整借用顺序或作用域。
- **误以为 `=` 是深拷贝**：对 `String`/`Vec` 等，`=` 是移动；对 i32 等 `Copy` 类型才是拷贝。
- 修编译错误时，**先读懂错误信息**，`cargo` 的提示通常直接告诉你改法（比如加 `&`、加 `mut`）。
