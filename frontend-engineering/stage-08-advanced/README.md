# 阶段八：进阶架构（按需深耕）

> 前六个阶段打牢地基后，按你实际遇到的场景选学。这里只列"为什么"和入口。

## 1. 微前端（Micro-Frontends）

**为什么**：当一个前端应用被太多团队同时维护，技术栈不统一、发版互相拖累、构建越来越慢。
微前端让**多个独立应用（可不同框架）组合成一个页面**，各自独立开发、部署、运行。

- **qiankun**：基于路由劫持的沙箱方案，老牌稳妥。
- **Module Federation（Webpack 5 / Rspack）**：在构建期就把远程模块当本地模块用，运行时共享依赖，更现代。

## 2. 性能工程

**为什么**：功能对了但慢，用户照样流失。性能工程是把"快"当作可度量、可优化的指标。

- **Web Vitals**：LCP（最大内容绘制）、CLS（布局抖动）、INP（交互延迟）等核心指标。
- **构建产物分析**：用 `rollup-plugin-visualizer` / `webpack-bundle-analyzer` 看谁占了体积。
- **构建提速**：持久化缓存、并行、排除不必要的转译（如 `node_modules` 跳过 Babel）。

## 3. 设计系统与规范化流程

- 设计系统：用代码统一「颜色 / 间距 / 组件」，让设计与研发说同一种语言（如 Tailwind、Theme 变量）。
- 规范化：代码评审清单、分支模型（Git Flow / Trunk-Based）、变更通知——把"人"的协作也工程化。
