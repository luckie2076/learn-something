# 阶段二：代码质量与开发规范

> 目标：让"人"和"机器"都按同一套规则协作。规范不是束缚，是降低团队沟通成本。

本阶段拆成三个**互不依赖**的独立子目录，每个都能单独学习、单独运行：

| 子目录 | 解决什么问题 | 核心工具 |
|--------|--------------|----------|
| [typescript/](./typescript) | 把错误从"运行时"提前到"编译时" | TypeScript |
| [babel/](./babel) | 把新语法转译成老浏览器能跑的写法 | Babel |
| [eslint-prettier/](./eslint-prettier) | 统一"对不对"与"丑不丑" | ESLint + Prettier |

## 它们如何协同（真实项目里）

三者常出现在同一个项目里，但职责不重叠：
- **TypeScript** 负责类型，编译期拦错；
- **Babel** 负责语法降级，让产物兼容旧环境；
- **ESLint + Prettier** 负责代码质量与格式，提交前自动校正。

> 学习时建议**逐个击破**（进对应子目录 `pnpm install && pnpm <script>`），理解后再回看它们怎么组合。
