# 第一章 · 描述 UI（Describing the UI）

> 教学导向：每节都先讲「为什么这样设计」，再看最小可运行代码。
> 运行方式：`pnpm install && pnpm dev`，打开终端给出的本地地址。
> 代码全部在 `src/App.jsx` 中按小节聚合展示，每个小节一个独立文件（如 `src/01-YourFirstComponent.jsx`）。

---

## 1. 你的第一个组件
**是什么**：组件就是「返回标签的 JavaScript 函数」。

**为什么是函数**：React 是声明式的——你描述 UI 长什么样，而不是一步步命令它怎么变。函数天生适合做这件事：**输入 = props，输出 = UI**。这让你像搭积木一样把小组件拼成复杂界面。

```jsx
export default function Profile() {
  return <div><h3>Katherine Johnson</h3></div>
}
```

> 约定：组件名**首字母大写**，否则 React 会把它当成普通 HTML 标签。

## 2. 组件的导入与导出
**为什么**：把组件拆到不同文件，每个文件只讲一件事——方便复用、阅读、维护。这是工程化的第一步。

- `export default` 导出组件，`import X from './X.jsx'` 导入。
- 一个文件通常只放一个主要组件。

## 3. 使用 JSX 书写标签语言
**是什么**：JSX 让你在 JS 里直接写类似 HTML 的标签。

**为什么是语法糖**：JSX 不是字符串，也不是真正的 HTML，它是 `React.createElement(...)` 的简写。浏览器不认识 JSX，由 Vite（借助 `@vitejs/plugin-react`）在编译期转成普通 JS 调用。这样你既能写熟悉的标签，又保留 JS 的全部能力。

> 错读：很多人以为 JSX 是模板语言。其实它编译后就是 `React.createElement(type, props, children)`，本质还是 JS。

## 4. 在 JSX 中通过大括号使用 JavaScript
**为什么**：JSX 负责“结构”，`{}` 负责“动态”。任何 JS 表达式都能塞进 `{}`——变量、计算结果、甚至属性值（`title={...}`）。这让静态标签和动态数据自然结合。

```jsx
<h3>{name} 的档案</h3>
<div style={{ width: 100 }} />   // 注意：style 里是对象，所以要两层 {}
```

## 5. 将 Props 传递给组件
**是什么**：props 是父组件传给子组件的只读数据，本质是函数参数。

**为什么只读**：第 8 节会讲“纯组件”——同样的输入必须得到同样的输出。子组件不能反向修改父组件的数据，才能保证**单向数据流**可预测、好调试。

```jsx
function Avatar({ person, size = 80 }) { /* ... */ }
<Avatar person={user} size={100} />
```

## 6. 条件渲染
**为什么**：JSX 没有 `if/else` 语法，所以借用 JS 的三招：
- `? :` 三元——二选一显示不同 UI；
- `&&` 短路——条件为真才渲染，否则渲染 `false`（React 会忽略 `false`）；
- 组件里提前 `return` 某个 UI。

核心认识：**条件渲染就是“用 JS 决定渲染什么”**，没有新概念。

## 7. 渲染列表
**为什么用 `map`**：数据和 UI 分离是 React 的核心理念——你维护数据数组，用 `map` 把它映射成一组组件。

**`key` 为什么必须**：React 重渲染时用 `key` 识别“哪个元素是原来的那个”，从而只更新变化项、复用不变项。⚠️ 不要用数组下标当 `key`（增删时下标会错位，导致状态串味）。

## 8. 保持组件纯粹
**是什么**：纯函数 = 同样的输入永远得到同样的输出，且不读写函数外部的“可变”状态。

**为什么对 React 致命重要**：React 可能多次调用你的组件（开发模式下 `StrictMode` 会故意渲染两次来帮你发现问题）。纯函数保证“多次调用结果一致”，否则会出现“点一下变了两次”“顺序诡异”的 bug。

```jsx
// 纯
function double(n) { return n * 2 }
// 不纯：改了外部变量
let cart = []
function add(item) { cart.push(item) }
```

## 9. 将 UI 视为树
**为什么**：React 把界面看成一棵树（App 是根，子组件往下嵌套）。理解这棵树有两个实际好处：
1. **props 只能从父流向子**（单向），你一眼就知道数据从哪来；
2. **渲染树**决定 UI 如何构建，**模块依赖树**决定代码如何打包——调试和性能优化都建立在这个心智模型上。
