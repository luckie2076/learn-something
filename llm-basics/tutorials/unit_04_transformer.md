# 04 · Transformer —— 组装完整模型，对"下一个 token"打分

> **角色**：第一个"组装者"——把 u02 的 embedding + 24 层 u03 的 attention + 输出层串联起来，
> 完成完整的前向传播，给词表中每个候选 token 打出"下一个是什么"的分数。

---

## 一句话理解

输入一段文字（token IDs），经过嵌入 → 24 层注意力 → 输出层（lm_head），
输出一个 `[seq_len, vocab_size]` 的**logits 矩阵**——
每行对应一个位置，行内的每个数字是"下一个 token 应该接 XX"的分数。

---

## 完整数据流（端到端）

以输入 **"中国的首都是"** 为例，逐步追踪形状和含义：

```
═══════════════════════════════════════════════════════════════
步骤 1: 分词（u01）
═══════════════════════════════════════════════════════════════
"中国的首都是"
  ↓ encode()
[12345, 67890, 11223, 44556, 77889]    ← 5 个 token
 "中"   "国"   "的"   "首"   "都"
  ↓ torch.tensor([[ids]])
[1, 5]                                  ← batch=1, seq_len=5

═══════════════════════════════════════════════════════════════
步骤 2: Embedding 查表（u02 逻辑，模型内部自动执行）
═══════════════════════════════════════════════════════════════
Embedding 权重表: [vocab_size, hidden_dim] = [151936, 896]

操作: 每个 token ID 去表中取对应一行
  ID 12345 → 表中第 12345 行的 896 个数字
  ID 67890 → 表中第 67890 行的 896 个数字
  ...

输出: [1, 5, 896]     ← batch=1, seq_len=5, hidden_dim=896
此时向量不含上下文，纯查表结果

═══════════════════════════════════════════════════════════════
步骤 3: 24 层 Transformer（u03 逻辑，模型内部自动执行）
═══════════════════════════════════════════════════════════════
每层做 causal attention（不偷看未来）:
  位置 0 "中" → 只看到 [中]
  位置 1 "国" → 只看到 [中, 国]
  位置 2 "的" → 只看到 [中, 国, 的]
  位置 3 "首" → 只看到 [中, 国, 的, 首]
  位置 4 "都" → 只看到 [中, 国, 的, 首, 都]

24 层迭代融合后:
输出: [1, 5, 896]     ← 形状不变，但每个向量已吸收上下文信息
位置 4 "都" 的向量包含了前面 4 个词的完整语义

═══════════════════════════════════════════════════════════════
步骤 4: lm_head 输出层 — 矩阵乘法打分 ★ 最关键的一步
═══════════════════════════════════════════════════════════════

lm_head 权重: [hidden_dim, vocab_size] = [896, 151936]

         ┌───────────────────────────────────────────┐
         │  列 0     列 1     列 2  ...  列 151935   │
         │  ("!")   ("的")   ("。")     ("某生僻字") │
         ├───────────────────────────────────────────┤
第 0 行  │  0.12     0.34     0.01  ...    -0.05    │
第 1 行  │ -0.67     0.01    -0.22  ...     0.89    │
  ...    │  ...      ...      ...   ...     ...     │
第 895 行│  0.23    -0.78     0.45  ...     0.12    │
         └───────────────────────────────────────────┘

操作: [1, 5, 896] @ [896, 151936] = [1, 5, 151936]

以位置 4 为例，它的 896 维向量 h_4 与每列做点积:
  score(列 j) = h_4[0] × W[0][j] + h_4[1] × W[1][j] + ... + h_4[895] × W[895][j]
  
一次矩阵乘法 → 同时给 151936 个候选打出分数！

═══════════════════════════════════════════════════════════════
最终输出: logits [1, 5, 151936]
═══════════════════════════════════════════════════════════════

含义:
  logits[0, 0, :] → "中" 后面该接什么？
  logits[0, 1, :] → "中国" 后面该接什么？
  logits[0, 2, :] → "中国的" 后面该接什么？
  logits[0, 3, :] → "中国的首" 后面该接什么？
  logits[0, 4, :] → "中国的首都是" 后面该接什么？ ← 我们取这行！

取 logits[0, -1, :] → softmax → 概率分布 → "北" 概率 72.34% 最高！
```

---

## 为什么叫"对下一个 token 打分"

模型是用 **Causal LM**（因果语言模型）方式训练的：

```
训练数据: [A, B, C, D, E]
         ↓
位置 0 输入 A，训练目标 = B    （让模型学会"后面是什么"）
位置 1 输入 B，训练目标 = C
位置 2 输入 C，训练目标 = D
位置 3 输入 D，训练目标 = E
```

因此每个位置的输出天然就是**对下一个 token 的预测**。

---

## lm_head 和 Embedding 的形状关系

```
Embedding 层: [vocab_size, hidden_dim]  即 [151936, 896]
              ↓ 输入是 ID，输出是向量

lm_head 层:   [hidden_dim, vocab_size]  即 [896, 151936]
              ↓ 输入是向量，输出是 ID 的分数
```

它们**互为转置**（行列互换）。很多模型会把它们共享权重（Weight Tying），节省参数。

---

## 对外接口

| 函数 | 输入 | 输出 |
|------|------|------|
| `forward(text)` | `"中国的首都是"` | `logits [1, 5, 151936]` |
| `predict_next(text, k)` | `"中国的首都是"` | `[("北", 72.34%), ("南", 5.12%), ...]` |
